# Consulting Strategy Deck Framework

Use this reference when building a data-backed marketing, brand, or campaign strategy PPT. Keep the logic modular: if the user gives a different industry, replace the category examples but preserve the derivation pattern. If the user supplies a more specific framework, use it as the authority and translate every module into `what data / what conclusion / demo` before writing slides.

## Default Pyramid

1. **Market / Calendar Context**  
   Show the planning window and why it matters. Use monthly demand, industry growth, price-band shift, category trend, or seasonal context.

2. **User Demand Differences**  
   Compare the user concerns by season, audience, scenario, or purchase stage. Use a split matrix or double-column comparison.

3. **Platform Behavior**  
   Show search, content, creator, conversion, or keyword behavior. Prefer search index and word-class structure over vague growth-rate claims.

4. **Why Big Event / Why Content Architecture**  
   Prove why normal product content is insufficient. Compare interaction rate, search rate, dwell, comment, share, live-entry, and lead behavior.

5. **Audience Penetration And Conversion Paths**  
   Show how the same event reaches different groups and how each group moves to search, live, consultation, single product, suite, or service.

6. **Scenario Trust / Product System Opportunity**  
   Show why users believe real scenarios, local creators, user reviews, or installation cases. Connect single-product interest to household solutions.

7. **Seasonal Emotional Or Functional Deep Dive**  
   For H2 decks, winter usually needs a separate page: do not reduce it to "more heat"; unpack softness, dryness, uneven temperature, energy anxiety, and companionship.

8. **Event Continuity / IP System Proof**  
   Show why one-off peaks decay and continuous IP creates memory, search, and category association.

9. **Strategy Model**  
   Summarize the macro打法. A useful triangle for appliance/marketing-event decks is:
   `IP体系化 × 年轻新锐化 × 套系生态化/价值套系化`.

10. **Execution Bridge**  
   Bridge to later creative or media planning. Use a 6-month roadmap and show how each month strengthens IP assets, young participation, and suite conversion.

## Default 10-Page H2 / Air Conditioner Pattern

Use this when the deck resembles the Gree H2 Douyin/event marketing pitch.

| Page | Role | Example Answer-Title | Data Objects |
| --- | --- | --- | --- |
| P1 | Monthly demand map | H2 is not three seasons, but six months of continuous user attention migration | Monthly line chart + monthly TOP concern heatmap |
| P2 | Seasonal concern split | Spring/summer wants "fast, cool, saving"; autumn/winter wants "warm, clean, suite" | Double-column comparison with spring/summer index vs autumn/winter index |
| P3 | Platform search logic | Douyin search is a monthly index and word-class structure problem | Keyword search index heatmap + word-class donut |
| P4 | Event necessity | Normal content explains products, but big events create active search | Interaction/search rate by content type + event uplift chain |
| P5 | Audience conversion | After a big event, each group penetrates and converts differently | Audience matrix or funnel/Sankey |
| P6 | Real household trust | Showrooms look good, but real homes are more credible | Trust-source ranking + household persona cards |
| P7 | Winter mind | Winter demand is more intimate, softer, and more companion-like | Pain-point bubbles + content resonance/conversion matrix |
| P8 | IP continuity | One event decays; continuous IP creates mental penetration | Single-event vs mother-IP retention comparison |
| P9 | Strategy model | IP systemization × young communication × suite value | Triangle model + KPI targets |
| P10 | Bridge to execution | Six monthly windows point to the execution architecture | 7月-12月 roadmap |

## Data Rules

- Use real sources when available: platform backend, 巨量算数, 抖音指数, 飞瓜, 蝉妈妈, brand backend, industry reports, retail panel data, search trend tools.
- If the user allows generated data, mark it as `策略假设数据，后续以平台后台替换`.
- Include enough numbers for the page to feel decision-grade. A single headline metric is usually not enough.
- Use index values when real absolute values are unavailable. Example: `快速制冷 春夏 92 vs 秋冬 28`.
- Tie every dataset to a strategic implication. Do not leave data as decoration.

## Style Rules

- Use the approved sample, brand system, template, or named style reference as the visual authority. Consulting structure does not require a blue corporate palette.
- Use a conclusion under the title; do not put a separate bottom conclusion when the user rejected it.
- Avoid oversized landing-page hero layouts for operational/strategy decks.
- Use cards only when they express real grouping. Prefer a flat canvas, one dominant chart, direct annotations, and restrained supporting evidence.
- Preserve user-supplied backgrounds if the user explicitly gives one.
